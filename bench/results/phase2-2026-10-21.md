# Phase 2 results: JSON reliability + OCR-verified health extraction (2026-10-21)

Commit under test: `29208e0`. Weights `config.txt`: `vision_default_output_length=140` (as phase 1).
Same device, build configuration, inputs and protocol as `baseline-2026-10-21.md`; 3 rounds
(`phase2-r1..r3.log`, verbose logging on). Changes are listed in `bench/experiments.md`.

## Reliability

| Metric | Baseline (5 rounds) | Phase 1 (3 rounds) | Phase 2 (3 rounds) |
|---|---|---|---|
| Prompt dropped | 9/26 text inferences | 0/11 | **0/12** |
| Model output that failed JSON parsing (`parse_failure`) | not logged | frequent, not counted (phase 2 diag: 4 in one IMG_9596 scan + Insights) | **0/18 inferences** |
| Output repaired by `LenientJSON` (`json_repair`) | n/a | n/a | 0/18 (every output was valid JSON as generated) |
| Output stopped by `max_tokens` | not logged | not logged | 0/18 |
| Model release / reload during a scan | 8 reloads over 5 rounds | yes (OCR fallback) | **0** |
| Insights succeeded on first attempt | 1/5 | 1/3 | **3/3** (1 inference each) |
| Vision `std::bad_alloc` | 5/10 scans | 0/6 | 0/6 |
| Run-to-run determinism | no | rounds 2-3 identical | **all 18 inferences identical** prefill/decode token counts in all 3 rounds |

With `repetition_penalty` off and temperature 0 every output was valid JSON without repair, which supports
the repetition-penalty explanation in `bench/experiments.md` (inferred from 3 identical rounds, not tested in isolation).

## Extraction accuracy (ground truth: 8 values in section 6, `bench/README.md`)

| Round | IMG_9603 | IMG_9596 |
|---|---|---|
| 1-3 (identical) | **2/8** correct value and status (Glucose 115 High, A1c 6.1 High) + BMI 25.7, 8-year risk 7 %; lipid panel missing | **8/8** correct value and status |
| Phase 1 for comparison | 0-2/8, invented values | 1-2/8, invented values |
| Baseline for comparison | 2-3/8 | 1-2/8 |

No wrong values were shown in phase 2: every displayed value is on the report.
Gemma 4 vision still invents values: OCR confirmed only 1-2 of its 8 metrics per scan, so the final result came
from Gemma 4 structuring the OCR text in all 6 scans (`path=ocr_text`).

IMG_9603 cause: with the longer OCR text of the flat scan (1,330 prefill tokens) the greedy text model returned only
the Key Findings block (4 metrics, 425 decode tokens, not truncated). Fixed after the benchmark in `bd0c74a`: known
metrics are also read from OCR table rows and fill keys the model left out. Offline check on the iPhone OCR lines
logged in r1-r3: IMG_9603 **7/8** (Cholesterol/HDL Ratio is dropped because OCR read "2.0" as "20"), IMG_9596 unchanged
8/8. The fix adds no inference; it is not yet confirmed in a device run.

## Latency (median of 3 rounds)

| Item | Baseline | Phase 1 | Phase 2 | Phase 2 range |
|---|---|---|---|---|
| Model load, cold | 7.1 s | | 7.8 s | 7.4-8.7 s |
| Finance summary | (prompt dropped) | 52.7 s | **40.5 s** | 39.1-40.6 s |
| Health scan IMG_9603 | 130.9 s | 115.6 s | 234.5 s | 212.8-242.0 s |
| Health scan IMG_9596 | 147.2 s | 373.4 s | **310.1 s** | 295.9-325.0 s |
| Health scan, all | 140.0 s | 180.3 s | 269.0 s | 212.8-325.0 s |
| Insights | 171.2 s | 294.7 s | **192.0 s** | 142.1-195.1 s |

Every scan now runs vision (96-170 s) and then OCR text structuring (115-154 s). IMG_9603 is slower than in
phase 1 because phase 1 returned the vision output (invented values) without a second inference.
Insights produced the same 749 tokens in every round; round 3 was faster only because decode ran at 5.7 tok/s
vs 4.2-4.3 (cause not determined).

| Inference | Prefill tokens | Decode tokens | TTFT | Decode tok/s |
|---|---|---|---|---|
| Finance (text) | 594 | 290 | 6.8-7.5 s | 8.7-9.0 |
| Vision IMG_9603 | 437 | 631 | 16.2-16.5 s | 7.7-7.9 |
| OCR text IMG_9603 | 1,330 | 425 | 22.8-25.1 s | 3.6-4.6 |
| Vision IMG_9596 | 441 | 655 | 16.5-29.5 s | 4.6-5.3 |
| OCR text IMG_9596 | 1,340 | 463 | 26.9-28.9 s | 3.7-3.9 |
| Insights (text) | 1,003 | 749 | 10.5-18.5 s | 4.2-5.7 |

Decode speed is lowest for the long-context inferences (1,000+ prefill tokens): 3.6-5.7 tok/s vs 8.7-9.0 for Finance.
That decode cost grows with context length is a hypothesis, not measured.
