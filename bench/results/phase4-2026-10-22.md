## Tokens and decode speed per inference

| Inference | Phase 3 prefill / decode | Final prefill / decode | Final decode tok/s |
|---|---|---|---|
| Finance | 532 / 153 | 532 / 189 | 10.1 |
| OCR text IMG_9603 | 1,222 / 42 | **654** / 42 | 9.2-9.5 |
| OCR text IMG_9596 | 1,218 / 57 | **634** / 54 | 9.3 |
| Insights | 929 / 479 (1,138 / 578 before split) | **592 / 182** | 9.1-9.4 |

Decode speed depends on context length on this CPU path: OCR-text decode went from 6.4-6.9 tok/s at
about 1,220 tokens of context to 9.2-9.5 at about 640; Insights from 5.1-5.9 tok/s (1,138 + 578) to
9.1-9.4 (592 + 182). Shorter prompts therefore speed up both prefill and every decoded token.

## Mac proxy check

`bench/mac_insights` rebuilds the Insights messages from a logged run and runs them with Cactus on the
Mac (same weights and Cactus source). For `phase4-r1..r3` the rebuilt messages matched the device
`messages_hash` (`6319927d7c343a45`) and the Mac answer was byte-identical to the iPhone's (2,135 chars).
The final prompt was drafted on the Mac (59 s per run before, 14 s after); the device then matched the
Mac's prediction exactly: hash `33e16ef99798e758`, 592 / 182 tokens, identical 640-char answer.
