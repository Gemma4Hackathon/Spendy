# Baseline: original on-device pipeline (2026-10-21)

Commit under test: `97ecd26` (original app logic + measurement-only instrumentation).
Device: iPhone 12 Pro (6 GB RAM), iOS 27.0.1. Xcode 27.1, Release build.
Model: Gemma 4 E2B + LoRA `EddieTsai123/gemma_4_e2b_lora`, Cactus INT4 (1959 files, 4.7 GB), cactus `d917981f` + `restore/cactus-d917981f.patch`.
Protocol: 5 rounds, each a cold launch then Finance summary, health scan of IMG_9603 (flat scan), health scan of IMG_9596 (photo of a screen), Insights. Inputs per `bench/README.md`.
Raw console logs are kept outside the repo (they contain model responses about the spending data).

## Reliability

| Issue | Rate |
|---|---|
| Prompt dropped (9 prefill tokens, 89-char reply "Please provide the text or image...") | 9 / 26 text inferences (35 %) |
| Finance received its full prompt | 0 / 5 (3 fully dropped; 2 at 122 prefill tokens vs 481 for the same-length input in the pilot) |
| Insights succeeded on first attempt | 1 / 5 (round 5 failed both attempts and needed a manual re-tap) |
| Vision `std::bad_alloc` | 5 / 10 scans (IMG_9596 4/5, IMG_9603 1/5), each at 2.05-2.21 GB footprint |
| Vision path produced the final result | 1 / 10 |
| Extra time spent unloading and reloading the model | 55.9 s over 5 rounds |

Root cause of dropped prompts (evidence-based hypothesis, to be confirmed by the fix): Spendy serializes messages with
`JSONSerialization` from Swift dictionaries, whose key order is not stable. Cactus's `parse_messages_json`
(`cactus/ffi/cactus_utils.h`) looks for `"content"` only after `"role"`, so when `content` is serialized first the content is lost.
Same-length inputs with different hashes (same content, different key order) give different results; identical hashes give identical results.
